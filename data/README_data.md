## 1. ЕМИСС (fedstat.ru): урожайность, площади, сборы, экономика
- **Скрипт:** `scripts/download/emiss.py <id> ...`. Поиск показателей делает `scripts/download/emiss_search.py`: сырые страницы поиска лежат в `data/raw/emiss/_search/`, сводка — в `data/interim/emiss/search_hits.tsv`, отобранные сельхозпоказатели — в `data/interim/emiss/agri_candidates.txt`.
- **Механизм:** скрипт парсит со страницы `/indicator/<id>` JS-объект `filters` со всеми фильтрами и значениями. Затем делает POST на `/indicator/downloadData.do?format=sdmx` с одноразовым токеном `struts.token` со страницы и параметрами `selectedFilterIds=<filter>_<value>`, куда включены **все значения всех фильтров**: все годы, регионы, ФО, РФ, категории хозяйств и культуры. Если полная выгрузка обрывается, скрипт качает её по годам (`data_<год>.xml`).
- **Формат:** SDMX-ML (Generic). В `CodeLists` есть справочники ОКАТО (`s_OKATO`), категорий хозяйств и культур, в `DataSet` — наблюдения. Рядом лежат `page.html` (паспорт показателя: методика, ведомство) и `filters.json` (разобранные фильтры с названиями).
- **Путь:** `data/raw/emiss/<id>/data.xml`.

## 2. Границы регионов и точки
- **Скрипты:** `geo.py` (границы), `regions_table.py` (справочник), `geo_points.py` (точки).
- `data/raw/geo/geoboundaries_RUS_ADM1*.geojson`: geoBoundaries gbOpen, ADM1 России, 83 субъекта, источник — OSM (Wambacher), лицензия ODbL, сборка 2023. Есть полная и упрощённая версии.
- `data/raw/geo/geoboundaries_UKR_ADM1*.geojson`: оттуда берутся полигоны Республики Крым, Севастополя, ДНР, ЛНР, Запорожской и Херсонской областей. Эти субъекты есть в ЕМИСС, а в RUS ADM1 их нет. Используются административные границы областей целиком.
- `data/raw/geo/click_that_hood_russia.geojson`: альтернативная граница, 83 региона, названия на русском (2013 г.).
- `data/raw/geo/regions.csv`: **таблица соответствия** для 89 субъектов: ОКАТО (как в SDMX ЕМИСС) ↔ название ЕМИСС ↔ ISO 3166-2 ↔ имя в geoBoundaries ↔ ФО. Особенности:
  - Полигон «Arkhangelsk Oblast» не включает НАО, а «Tyumen Oblast» — ХМАО и ЯНАО. В ЕМИСС для них есть и коды «без АО» (11001000000, 71001000000), и коды «с АО» (11000000000, 71000000000). В таблице для Тюмени стоит код 71001000000.
  - Новые субъекты в справочнике ОКАТО ЕМИСС 31533 **не встречаются** (по ним нет урожайности). Их коды ОКАТО (21, 43, 23, 39) проставлены по ОКАТО, при склейке их надо проверить.
- `data/raw/worldcover/ov64/*.npy`: обзорный уровень 1/64 (~640 м) тайлов ESA WorldCover 2021 v200, которые нужны для отбора точек. Класс 40 означает пашню (cropland).
- `data/raw/geo/points.csv`: **450 точек** в 89 субъектах. Поля: `point_id, okato, region, iso3166_2, lat, lon, method, crop_frac_3km, wc_class_center, rank_in_region, region_crop_km2_est`.
  - `method=worldcover_cropland_fps` (428 точек): регулярная сетка примерно из 600 узлов внутри полигона, отбор узлов с долей пашни ≥ 0.25 в окне ~3×3 км, затем разнос точек по региону (farthest-point sampling). Число точек N = площадь пашни / 2500 км², в пределах 2–15; при пашне больше 8000 км² — не меньше 5.
  - `method=fallback_south` (22 точки): северные регионы без пашни в WorldCover (Якутия, Мурманская область, ХМАО и др.). Взяты 1–2 точки в южной части региона, вне воды, снега и застройки.
  - Получилось: Ростовская, Саратовская, Оренбургская области и Алтайский край — по 15 точек, Волгоградская — 13, Ставропольский край — 12, Краснодарский край — 11, северные регионы — 1–2.
  - `rank_in_region=0` — «главная» точка региона с максимальной долей пашни. С неё начинаются загрузки по каждому региону.

## 3. Погода
### 3a. Open-Meteo Archive API — пробные запросы
- Бесплатный лимит не позволяет скачать ряды для сотен точек. После трёх запросов (по 3 точки, 2000–2026 гг., 11 суточных переменных) API ответил `Hourly API request limit exceeded`. Вес запроса растёт с числом точек, дней и переменных: полный 26-летний ряд для одной точки «стоит» сотни вызовов при лимите 10 000 в сутки.
- Пробный ответ (3 точки, суточные данные) сохранён в `data/cache/om_test_1.json`.

### 3b. ERA5 и ERA5-Land из открытого бакета Open-Meteo на AWS — **основной источник погоды**
- **Скрипт:** `scripts/download/era5_openmeteo_s3.py <model> <var> ...`
- **Источник:** `s3://openmeteo/data/<model>/<var>/` (anonymous, без ключа). Это те же данные, которые отдаёт archive-api.open-meteo.com, но без лимита API. Чтение идёт пакетом `omfiles`, точечными запросами по диапазонам байтов.
  - Файлы `year_YYYY.om` есть по 2021 г. включительно. С 2022 г. идут файлы `chunk_N.om` (N×504 ч от 1970-01-01 UTC), последний — примерно до начала октября 2026.
  - `copernicus_era5`: сетка 0.25°. Переменные: precipitation, shortwave_radiation, temperature_2m, dew_point_2m, wind_u/v_component_10m, snowfall_water_equivalent, cloud_cover, soil_moisture_0_to_7/7_to_28/28_to_100cm, soil_temperature_0_to_7cm, wind_gusts_10m, direct_radiation.
  - `copernicus_era5_land`: сетка 0.1°. Переменные: temperature_2m, dew_point_2m, soil_moisture_0_to_7/7_to_28/28_to_100/100_to_255cm, soil_temperature_0_to_7/7_to_28/28_to_100cm, snow_depth. В бакете ERA5-Land нет осадков и радиации, они берутся из ERA5.
- **Охват:** все 450 точек (ERA5 — 436 уникальных ячеек, ERA5-Land — 447), **почасово**, с 2000-01-01 до последнего доступного часа.
- **Формат:** `data/raw/era5_om/<model>/<var>/<year_YYYY|chunk_N>.parquet`. Индекс `time_utc`, по одной колонке на ячейку сетки `iy_ix`. Связь точек с ячейками — в `data/raw/era5_om/<model>/cells.csv`.
- **Проверка:** осадки 2010-07-01..03 в точке (45.0, 39.0) совпали с ответом API Open-Meteo. Tmax отличается примерно на 1 °C: API смешивает ERA5 и ERA5-Land, а сравнивалось с ERA5 0.25°.
- **Единицы** (как в Open-Meteo): °C, мм за час, Вт/м² (средняя за час), м³/м³, км/ч или м/с — уточнить по документации Open-Meteo. Время в UTC: суточные агрегаты надо считать с поправкой на часовой пояс.
- **Ограничения:**
  - ERA5-Land над морем даёт NaN, в прибрежных точках (Севастополь, Калининград) стоит смотреть ERA5.
  - Расчётных переменных Open-Meteo (ET0, VPD, sunshine) в бакете нет. Их нужно считать самим по формуле FAO-56 из T, Td, радиации и ветра.

### 3c. NASA POWER (второй источник погоды)
- **Скрипт:** `scripts/download/nasa_power.py`. **Путь:** `data/raw/nasa_power/<point_id>.csv` — сырой CSV ответа API с заголовком.
- **Охват:** 450 точек, суточные данные с 2000-01-01 по вчерашний день, время LST, сообщество AG. Сетка MERRA-2 0.5°×0.625°, радиация CERES 1°.
- **Параметры:** T2M, T2M_MAX, T2M_MIN, T2MDEW, PRECTOTCORR, ALLSKY_SFC_SW_DWN, CLRSKY_SFC_SW_DWN, RH2M, QV2M, WS2M, WS2M_MAX, PS, GWETTOP, GWETROOT, GWETPROF (влажность почвы 0–1), TS, EVLAND, SNODP, FROST_DAYS, ALLSKY_SFC_PAR_TOT. Пропуски обозначены как −999.

## 4. Почвы — SoilGrids 2.0 (ISRIC)
- REST `rest.isric.org/soilgrids/v2.0/properties/query` проверен: короткий запрос проходит примерно за 3–12 с, а полный (13 свойств × 5 глубин × 5 статистик) не укладывается в 180 с. Основной путь поэтому — глобальные COG/VRT `files.isric.org/soilgrids/latest/data/` (та же модель, 250 м), точечное чтение через rasterio. Значение clay в точке (45.0, 39.0) совпало с REST (451).
- **Скрипт:** `scripts/download/soilgrids.py`. **Путь:** `data/raw/soilgrids/soilgrids_points.csv` в длинном формате: `point_id, lat, lon, property, depth, stat, value_raw`.
- **Охват:** 450 точек. Свойства: clay, sand, silt, soc, phh2o, nitrogen, cec, bdod, cfvo, ocd, wv0010, wv0033, wv1500 (влагоёмкость при 10/33/1500 кПа); ocs — только 0–30 см. Глубины: 0–5, 5–15, 15–30, 30–60, 60–100 см. Статистики: mean, Q0.05, Q0.5, Q0.95, uncertainty.
- **Единицы:** целые числа в mapped units SoilGrids (clay/sand/silt — g/kg; soc — dg/kg; phh2o — pH×10; nitrogen — cg/kg; cec — mmol(c)/kg; bdod — cg/cm³; cfvo — cm³/dm³; ocd — hg/m³; ocs — t/ha). **−32768 = нет данных** (вода, город).

## Пробелы и ограничения

1. **ЕМИСС: 13 показателей без данных** (4 требуют аккаунта, 9 исключены из реестра, список выше). Площадь орошаемых земель в открытом виде не получена.
2. **Новые субъекты** (ДНР, ЛНР, Запорожская, Херсонская области) в урожайности ЕМИСС отсутствуют, хотя точки погоды и почв для них есть.
3. **ERA5:** у cloud_cover (ERA5) в бакете Open-Meteo есть только 22 годовых и 50 chunk-файлов (скачано 71 из них), у soil_moisture_* (ERA5) — 102 файла, у snow_depth (ERA5-Land) — 89: остальных файлов в бакете нет, повторные запуски ничего не добавили. Для облачности, влажности почвы и снежного покрова за 2022–2026 возможны дыры; проверять по `time_utc` в parquet.
4. **SoilGrids:** 10 свойств × 5 глубин × 5 статистик плюс ocs (0–30 см) для 450 точек, а также класс почвы WRB (`wrb_points.csv`, коды в `wrb_class_codes_alphabetical.csv`). **Слоёв wv0010, wv0033, wv1500 (влагоёмкость почв) на files.isric.org нет** (404), только в REST-сервисе, который не отвечает за разумное время. Рельеф и тип почвы ERA5 для ячеек: `data/raw/era5_om/<model>/static_cells.csv`.
5. **NDVI MODIS:** точки с `rank_in_region ≤ 2` (220 точек, 21 тайл, 602 даты 2000-02-18…2026-09-30) готовы полностью. Остальные 230 точек (`rank ≥ 3`) докачиваются (`run_modis_loop.sh 99 3`), статус — в строке сводной таблицы. EVI не читался.
6. **MapSPAM 2020:** требует анкеты (guestbook), не скачан.
7. **Росстат (Wayback):** 16 файлов раздела не сохранены в архиве (K_so_2025, Les, Ohota, Potr_RF, Realis_*_2025, mtbs-2_2025, oxr_bio, `zerno_2026-08.zip` и др.). `met_378-01082025.pdf` обрезан (`.partial`). ВСХП-2016: получено 16 файлов из 18, не удалось `Tom4_kn2.pdf` и `VSHP-2016.PDF`.
8. **Open-Meteo Archive API** (по заданию) не использован из-за часового лимита; вместо него ERA5/ERA5-Land из открытого бакета Open-Meteo (те же данные). Расчётных переменных (ET0, sunshine) там нет: их надо считать по формуле FAO-56 из температуры, точки росы, радиации и ветра.
9. **Минсельхоз:** собраны только новости с темой урожая (сырой HTML); отдельных таблиц с предварительными итогами по регионам на сайте не найдено.
10. **Не сделано:** нормативы затрат на гектар (технологические карты) — открытых таблиц не найдено; в FAO Crop Calendar API нет России.
