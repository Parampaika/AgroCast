# Контракт данных веб-интерфейса (`web/data/`)

Сайт `web/` читает только JSON-файлы из `web/data/`. Сейчас их собирает `src/web_export/make_mock.py`:

```bash
uv run python -I -X utf8 src/web_export/make_mock.py
```

Реальные результаты модели выгружаются **в тот же формат** другим скриптом (например, `src/web_export/export_model.py`): достаточно перезаписать нужные файлы и поставить `"mock": false`. Интерфейс менять не нужно.

## Общие правила

- **Ключи:** `okato` — 11-значный код субъекта, как в `data/clean` (Тюменская обл. — `71001000000`, РФ — `643`); `crop_code` — код культуры ЕМИСС (строка).
- **Единицы:** урожайность — т/га, площадь — тыс. га (`area_kha`), объём — тыс. т (`*_kt`), цены — руб./т, затраты — руб./га, проценты — в процентах (8,5 = 8,5 %).
- **Пропуски** — `null` (NaN в JSON запрещён).
- **Сезон прогноза** — `meta.season` (сейчас 2026).
- **Блок `meta`** в каждом файле:

| поле | тип | смысл |
|---|---|---|
| `mock` | bool | `true` — значения условные (заглушка), интерфейс показывает плашку «демо-данные» |
| `season` | int | год урожая |
| `source` | str | откуда данные |
| `note` | str | пояснения к полям |
| `generated` | str | время сборки, `YYYY-MM-DD HH:MM` |

## Файлы

| файл | mock сейчас | что внутри |
|---|---|---|
| `regions.geojson` | нет | Границы субъектов |
| `crops.json` | нет | Культуры прототипа |
| `history.json` | нет | Урожайность, тренд, площадь, сбор 2000–2026 |
| `forecast.json` | **да** | Прогноз «регион × культура × дата» |
| `drivers.json` | **да** | Факторы погоды в прогнозе |
| `weather_season.json` | нет | Погода сезона против нормы |
| `soils.json` | нет | Почвы пашни |
| `scenarios.json` | **да** | Урожайность по погодным сценариям для оптимизации |
| `economics.json` | **да** (затраты) | Цены, затраты, поправки калькулятора |
| `metrics.json` | **да** (предварительная модель) | Точность модели и бейзлайнов |

### `regions.geojson`

FeatureCollection, 89 субъектов, упрощённые полигоны geoBoundaries ADM1 (RUS + UKR для Крыма, Севастополя и новых субъектов). Координаты — градусы WGS84; долготы восточнее 180° (Чукотка) записаны как `lon + 360`, чтобы полигон не рвался. Проекцию (коническая Ламберта) делает интерфейс.

`properties`: `okato`, `name` (короткое русское название), `fo` (федеральный округ), `macro`, `is_city`, `is_new_subject`, `lat`/`lon` — центроид пашни.

### `crops.json`

`crops[]`: `crop_code`, `slug` (`winter_wheat`, `spring_wheat`, `barley`, `maize`, `sunflower`, `soy`, `sugar_beet`), `name`, `short`, `icon` (имя иконки в `web/js/icons.js`), `color` (HEX), `max_share` (максимальная доля культуры в севообороте, 0–1, допущение), `plant_month`, `maturity_month` (медиана календаря GGCMI).

### `history.json`

```json
{ "years": [2000, …, 2026],
  "series": { "<okato>": { "<crop_code>": {
      "yield": [т/га | null, …],      // ЕМИСС 31533, все категории хозяйств
      "yield_est": [т/га | null, …],  // только 2025: сбор / посевная (итогов Росстата ещё нет)
      "trend": [т/га | null, …],      // линейный тренд по 12 предыдущим годам (без года t)
      "area_kha": […], "gross_kt": […] } } } }
```

Массивы выровнены по `years`. Регион `643` — РФ в целом.

### `forecast.json`

```json
{ "dates": [{"id": "05-01", "label": "1 мая"}, …, {"id": "final", "label": "Конец сезона"}],
  "regions": { "<okato>": { "<crop_code>": {
      "trend": 5.81,           // тренд сезона, т/га
      "area_kha": 1627.8,      // площадь для объёма (сейчас — посевная 2025 г.)
      "source": "model_2026",  // или "mock"
      "by_date": [ {"date": "05-01", "p10": …, "p50": …, "p90": …,
                    "w_lo": …, "w_hi": …, "dev_trend_pct": 8.0, "volume_kt": …}, … ] } } } }
```

- `by_date` выровнен по `dates` (5 дат: 1 мая, 1 июня, 1 июля, 1 августа, конец сезона).
- `p10`/`p50`/`p90` — квантили прогноза, т/га (80 % интервал с учётом погоды и ошибки модели).
- `w_lo`/`w_hi` — разброс только погодных сценариев, т/га (внутренняя полоса веера).
- `dev_trend_pct` — `(p50 / trend − 1) × 100`.
- `volume_kt` — `p50 × area_kha`, тыс. т.
- Регионы с площадью культуры < 1 тыс. га не выгружаются.

Заглушка: итоговое отклонение от тренда — из предварительной модели (`reports/tables/forecast_2026_regions.csv`), где она есть, иначе случайное в пределах исторического разброса; к ранним датам известна только часть отклонения; ширина интервалов — из `reports/tables/intervals_calibrated.csv` и `leadtime_metrics_ens_lin.csv`.

### `drivers.json`

`regions.<okato>.<crop_code>` — до 6 факторов, по убыванию |вклада|:

| поле | смысл |
|---|---|
| `feature` | признак, `<переменная>_<месяц>`, например `sm28_100_03` |
| `label` | подпись для человека: «Влага в почве в марте» |
| `unit` | единицы аномалии |
| `anomaly` | аномалия сезона против нормы 2001–2021 (реальная) |
| `contrib_pct` | вклад в отклонение прогноза от тренда, п.п. (заглушка; в модели — SHAP) |

### `weather_season.json`

`months` — 14 подписей (сентябрь прошлого года … октябрь года урожая), `vars` — единицы. `regions.<okato>.<var>` = `{"fact": [14 значений], "norm": [14 значений]}` для `tmean` (°C), `prec` (мм), `htc` (ГТК, `null` в холодные месяцы). Норма — средняя 2001–2021.

### `soils.json`

`regions.<okato>`: `clay`, `sand`, `silt` (%), `soc`, `nitrogen` (г/кг), `ph`, `ocs` (т/га, 0–30 см), `wrb` (класс WRB), `wrb_share` (доля точек пашни). SoilGrids 2.0, слой 0–30 см.

### `scenarios.json`

```json
{ "scenario_years": [2005, …, 2025],
  "regions": { "<okato>": { "<crop_code>": [т/га × len(scenario_years)] } } }
```

Сценарий *s* — урожайность сезона при погоде года *s*. Одна и та же позиция у разных культур — один и тот же сезон: так сохраняется совместность (засуха бьёт по всем культурам сразу). Заглушка: `тренд сезона × (1 + отклонение от тренда в году s)`. В реальной выгрузке — прогон модели по погоде прошлых лет. Интерфейс сам переводит урожайность в прибыль на гектар.

### `economics.json`

| поле | смысл |
|---|---|
| `assumption` | `true`: затраты — допущения |
| `crops.<crop_code>` | `product` (код продукта цены), `cost_rub_ha` (полные затраты, руб./га, допущение), `price_rf_rub_t` (цена РФ) |
| `region_prices.<okato>.<crop_code>` | цена производителей, руб./т (ЕМИСС 57693, январь–сентябрь сезона; подстановка субъект → ФО → РФ) |
| `adjustments.soil/variety/tech[]` | поправки калькулятора: `id`, `label`, `yield_mult`, `cost_mult`, `risk_mult` (только у сортов: масштаб разброса) |

### `metrics.json`

- `methods` — названия методов: «прошлый год», «среднее 5 лет», «линейный тренд», «тренд × погода».
- `accuracy[]`: `crop_code` и по каждому методу `{mae (т/га), mape (%)}` — скользящая проверка 2012–2025.
- `leadtime[]`: `crop_code`, `cutoff` («1 апр» … «конец»), `mape`, `skill_pct` (снижение MAE к линейному тренду, %).

## Как подставить реальные результаты

1. Модель выдаёт таблицу «регион × культура × дата» с квантилями → пишем `forecast.json` (`mock: false`).
2. SHAP-вклады погоды по региону и культуре → `drivers.json`.
3. Прогон модели по погоде прошлых сезонов → `scenarios.json`.
4. Итоговые метрики перебора (`reports/sweep.md`) → `metrics.json`.
5. Проверить: `uv run python -m http.server -d web 8000`, плашки «демо-данные» исчезнут у блоков с `mock: false`.
