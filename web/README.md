# Агрокаст — веб-прототип калькулятора урожайности

Статический сайт без сборки: HTML + CSS + ванильный JS (ES-модули) и [Apache ECharts 5.5.1](https://echarts.apache.org/) (лежит в `vendor/`, лицензия Apache-2.0 — `vendor/echarts.LICENSE.txt`). Работает без интернета, подходит для GitHub Pages из папки `web/`. Решение участника конкурса, кейс «Своё Фермерство», задача 5; не продукт банка.

## Запуск

```bash
uv run python -m http.server -d web 8000
```

Открыть <http://localhost:8000>. Файл `index.html` напрямую (через `file://`) не откроется: браузер не даст загрузить JSON и модули.

Для разработки удобнее сервер без кэша — правки JS видны сразу:

```bash
uv run python -I src/web_export/serve.py 8000
```

Пересобрать данные (≈1 мин, ~1 МБ JSON):

```bash
uv run python -I -X utf8 src/web_export/make_mock.py
```

## Экраны и принцип подачи

Сайт открывается **стартовой страницей-визиткой** («О проекте»): что это, четыре входа, как работает, проект в цифрах, границы, автор и материалы. Главный продукт — **калькулятор участка** (задание кейса: ввод параметров участка → т/га и общий объём → польза для затрат и доходов). Региональная модель — «под капотом»; карта и региональный прогноз — раздел контекста. Принцип подачи: сначала одна главная мысль, подробности — по запросу («Подробнее», вкладки).

Честная формулировка: климат и погода региона и сезона — из обученной модели; влияние почвы, сорта и агротехники — множители-допущения (открытых данных об урожайности по сортам и агротехнике хозяйств нет). Прогноз для участка = прогноз региона («среднего хозяйства региона»), скорректированный на почву, сорт и агротехнику. Это сказано в поповере «Как считается».

| экран | адрес | на первом экране | по запросу |
|---|---|---|---|
| О проекте (по умолчанию) | `#/`, `#/home` | Название, два предложения, главная кнопка «Рассчитать урожай моего участка», четыре карточки-входа, «Как это работает» (3 шага), «Проект в цифрах» (17 источников, 683 столбца модели, регионы × культуры из `forecast.json`, > 1 000 конфигураций, −30 % ошибки к «прошлому году»), «Честно о границах», подвал: автор, репозиторий, презентация и отчёт (PDF), Telegram | — |
| Калькулятор | `#/calc` | «Параметры участка»: регион, дата, почва, сорт семян, агротехника, своя поправка, план посевов **в гектарах** по культурам (независимые поля); ниже — общий сбор, выручка, маржа, таблица по культурам (т/га, сбор, выручка, затраты, маржа), плохой / обычный / хороший год, блок «Что это даёт для планирования» | «Подробнее»: маржа по культурам; поповер «Как считается» |
| Регионы | `#/overview` | Главный вход «Рассчитать урожай моего участка» + «Прогноз по регионам» и «Что посеять», карта России, одно число — сбор по России, переключатель даты | «Подробнее»: как уточняется прогноз, регионы выше и ниже обычного; клик по региону — карточка |
| Карточка региона | `#/region/<okato>` | Вывод одной фразой, 4 числа, главный график (история + веер прогноза) | Вкладки: почему такой прогноз, погода сезона, почвы, все культуры региона |
| Оптимизация | `#/optimize` | Вывод («Переведите X % площади…»), ползунки переноса и осторожности, «было → стало» | «Подробнее»: кривая «сколько меняем → сколько выигрываем», прибыль по сезонам, допущения; «Весь регион целиком» |
| Методика | `#/method` | Источники, схема расчёта | точность против простых правил, ограничения |

- Дата прогноза: 1 мая … 1 августа — прогноз; «Итог сезона» — **оценка по фактической погоде сезона**, а не прогноз (так подписано везде).
- Вместо россыпи плашек — значок «i» с поповером «Данные и допущения».
- Ссылка с суффиксом `?open` (например `#/optimize?open`) раскрывает все «Подробнее» — удобно для скриншотов.
- Светлая и тёмная тема (по системе или кнопкой), контраст текста не ниже WCAG AA, адаптивная вёрстка до 360 px.

Числа на стартовой странице — из отчётов проекта (`reports/ladder.md`, `reports/preprocess.md`, `reports/sweep.md`, `deck/script.md`); число регионов и культур считается из `data/forecast.json`. PDF презентации и научного отчёта лежат в `materials/` (копии из `deck/out/` и `report/out/`; при пересборке обновить вручную).

## Данные: что реальное, что заглушка

Реальные (из `data/clean`): границы, история урожайности и площадей, тренды, погода сезона и нормы, почвы, цены производителей. Итоговые модели и оптимизация выгружены в те же файлы (`"mock": false`). Допущениями остаются затраты на гектар и поправки калькулятора (подписаны в поповерах «i»). Файл с `"mock": true` получает значок «Демо-данные» автоматически.

## Как подставить реальные результаты модели

Записать файлы `forecast.json`, `drivers.json`, `scenarios.json`, `metrics.json` в формате [docs/06_ui_data_contract.md](../docs/06_ui_data_contract.md) с `"mock": false`. Код сайта менять не нужно.

## Оптимизация

Матрица «культура × сценарий → прибыль на 1 га» = урожайность сценария × поправки × цена − затраты. Цель — `(1 − λ) · средняя прибыль + λ · средняя прибыль худших 20 % сезонов`, где λ — «осторожность». Ограничения: сумма долей = 1, доля культуры ≤ `max_share`, перенесённая площадь ≤ X, новые культуры — только отмеченные. Убывающая отдача: изменение доли культуры на Δ снижает выручку на `β·Δ²/2` (предшественники, худшие участки, перестройка севооборота). Решатель — жадные переносы площади шагом 0,5 %, задача вогнутая, поэтому результат близок к оптимуму.
